# Phase 1 follow-ups: rulings and deferred review findings

Recorded during subagent-driven execution of `2026-11-05-phase1-rust-timeline-foundation.md`. Rulings are decisions taken on the plan's behalf, with what each costs if wrong. Deferred items were judged non-blocking by task or final reviews.

## Rulings
- Ruling R1: Task 3 creates the TS harness, generator and one TS-side case (`toggle_mute_main`) with a bun self-test; `parity.rs` and `assert_golden` are created in Task 4 — keeps every commit green — cost if wrong: none, file just moves one task.
- Ruling R2: Task 2 fixtures are generated by a bun script using the app's own builders (element-utils, keyframe/effect/mask helpers) and storage serialization, not exported from a running app — subagents cannot drive the app; generated fixtures exercise the same shapes — cost if wrong: a real-world field shape missed, caught later by the unknown-field passthrough.
- Ruling R3: The parity harness applies TS ripple (computeRippleAdjustments + applyRippleAdjustments) after the command when a case sets ripple, mirroring CommandManager — needed for delete_ripple parity — cost if wrong: ripple goldens wrong.
- Ruling R4: Task 10 keeps CommandManager.applyRippleIfEnabled for non-ported commands; ported commands set `handlesRipple = true` and pass ripple to wasm, and CommandManager skips its ripple pass for them — removing it would break ripple for paste/keyframe/effect commands — cost if wrong: small extra flag.
- Ruling R5: Task 1 records a `bun test` / `bun run build:web` baseline before changes; "no regression" means no new failures vs baseline — cost if wrong: a pre-existing failure masks a new one with the same test name.
- Ruling R6: Hosted web (Vercel, mangocut.jonam.dev) must keep building. Fix round 1 also makes `build:wasm:all` self-provision rustup + wasm32 target + wasm-pack when missing and running in CI/Vercel (env CI or VERCEL set), instead of failing — spec requires Rust timeline in both web and engine — cost if wrong: slower Vercel builds (~1–3 min).
- Ruling R7: Overrides Global Constraint "Rust stores ticks as i64". Tick fields become a `Ticks` newtype over f64 that round-trips the exact JSON number (integers stay integers via js_number), so every existing project loads and Rust op math can mirror TS float math for parity. Ops needing whole frames call an explicit rounding helper. Rounding at the TS write sites is NOT done in Phase 1 (behaviour change) — follow-up noted for later. — spec's hard requirement is loading every project + TS parity — cost if wrong: Rust carries float ticks like TS; a later cleanup can normalise.
- Ruling R8: Overrides plan Task 4 "retime: round to nearest tick" and the `i64` tick fields in the TimelineOp sketch. All tick-valued op fields (splitTime, trimStart, trimEnd, startTime, duration, newStartTime) are `Ticks`; retime/placement math mirrors TS float math exactly with no rounding — required for golden parity under R7 — cost if wrong: Rust keeps TS's fractional-tick behaviour until a later normalisation pass.
- Ruling R9: From Task 8, apply_op returns typed `element_not_found` / `track_not_found` for unknown ids in every op (agent usability, plan Task 8). Goldens get an `expectedError` code field for such cases; TS adapters in Task 10 treat these two codes as a no-op where the UI relied on TS's silent no-op — cost if wrong: a UI path that relied on silent no-op surfaces an error until mapped.
- Ruling R10 (for Task 9): the TS wasm wrapper over-provisions ids (pool of max(32, 8 × elements referenced by the op) UUIDs; unused ids are harmless) and retries once with a doubled pool on `missing_ids`; it strips `undefined`-valued keys from patches before crossing to wasm (TS spread drops them on JSON); serde-wasm-bindgen uses serialize_maps_as_objects(true) — keeps id counting out of callers — cost if wrong: wasted UUID generation only.
- Ruling R11 (for Task 10): an UpdateElements patch key explicitly set to `undefined` in TS means "remove the field" (spread + JSON). The Task 10 adapter converts such keys to `null`, and Rust update treats `null` on any patch key as "remove key" (generalising today's retime-only rule) — keeps UI clears (e.g. updateElementRetime({retime: undefined})) working through the wrapper's undefined-stripping — cost if wrong: a field that legitimately holds null can't be set to null via patch.
- Ruling R12: `ApplyOpOptions` gains `validate: bool` (serde default true). UI command adapters (run-timeline-op used by the 10 ported commands when invoked from the editor UI) pass `validate: false`, preserving old TS permissiveness exactly (retime growth overlaps, resize sub-frame rounding); agent paths (commands-api handlers, later the engine) keep `validate: true`. — spec: Phase 1 must not regress the editor; strict contract is for the agent — cost if wrong: the UI can still create overlaps exactly as before Phase 1.
- Ruling R13: agent handlers that edit after an await (import_media_paths, generate_captions, cut_on_speech, remove_fillers, highlights) run permissive, not strict. Not a regression (pre-Phase-1 was permissive everywhere); the in-renderer commands-api agent path is replaced in Phase 4 by engine tools calling apply_op with validate:true and retired in Phase 8 — cost if wrong: until Phase 4, an agent edit that creates an overlap commits instead of returning invalid_result.
- Ruling R14: Final fix wave covers Critical 1–3, Important 4–7, plus moving wasm-commands.test.ts to its own process run and pinning wasm-pack. Important 4 is fixed for synchronous agent handlers now (overrides the Task 10 "defer to Phase 4" note for those); after-await handlers stay under R13. Critical 3 cannot be verified without a Vercel preview deploy — fixer adds the in-repo build hook and documents the required dashboard setting; flagged to the user as unverified — cost if wrong: first Vercel deploy after merge fails.
